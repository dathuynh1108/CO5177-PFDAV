Team & scope

Groups of 2–3 students complete three data tracks: Tabular and Text are mandatory; the third is selected from Image, Multimodal or Time series.

Our two-member team has selected Tabular, Text and Image.

  • Register a unique team name in GroupRegistration.
  • Enter the public landing-page URL in GroupLink.
  • Complete dataset registration as required by the course.

Dataset requirements

01 / Tabular

At least 2,000 samples and 10 columns, including missing values, categorical features for encoding and numerical features for scaling. Challenging data, such as imbalance and outliers, is encouraged.

02 / Text

At least 2,000 text samples. Vietnamese-language datasets are encouraged for Vietnamese students. Self-collected corpora are valued.

03 / Image

At least 5,000 images in total and at least 3 classes for classification. A short edge of at least 128 px is recommended; smaller images require justification and a handling strategy.

MNIST, Fashion-MNIST and CIFAR-10 are not accepted as the main dataset. When using deep learning, pretrained models are required. Explain splitting, leakage prevention and augmentation. Extended vision tasks require appropriate annotations and dataset documentation.

Avoid duplicate dataset choices where possible. Teams using the same dataset may be compared on originality and differences in approach.

Notebook workflow

Each data track uses a separate .ipynb notebook that runs completely on Google Colab with Run all.

  1. Describe the dataset: explain the source and context in Markdown; visualize its characteristics.
  2. Prepare the data: handle missing values and outliers, encode or scale when applicable, and define train, validation and test splits.
  3. Analyze and model: train suitable models and compare approaches or parameter settings.
  4. Conclude and extend: report metrics and visual findings, then discuss limitations and possible improvements.

The course encourages basic Scikit-learn models. Deep learning components may be treated as ready-to-use feature extraction or training functions.

Submission checklist

Public GitHub Pages website

  • Course, university, faculty, semester and instructor information.
  • Registered group name, member names, student IDs and individual contributions.
  • Real member GitHub links where available and the project repository.
  • Clear navigation to a separate page or section for each assignment.

For every assignment

  • Assignment title, data type, group name and members.
  • Problem and dataset description.
  • A runnable notebook link on GitHub and/or Google Colab.
  • A PDF report and a YouTube presentation video.

Videos should be public or unlisted; 5–10 minutes is recommended. Check all links before submission.

Final LMS report

One representative submits the consolidated PDF report to the LMS, named <groupname>-report.pdf. This does not replace the landing page or per-assignment reports and videos.

DeadlinesFollow the course LMS for registration and end-of-course deadlines. The assignment brief does not specify a calendar date.

What counts as an extension?

A figure or table should answer a meaningful question, include a conclusion and provide a quantitative comparison. Cosmetic changes alone do not earn creativity credit.

  • Tabular: compare preprocessing strategies or a baseline with an extended model.
  • Text: compare TF-IDF and embeddings or explain class-specific errors with examples.
  • Image: compare pretrained-feature classifiers and transfer learning on the same test set.

Running end to end is mandatory, not bonus credit. Proposed work must be implemented and supported by results to count as an extension.
